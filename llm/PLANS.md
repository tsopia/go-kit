# ExecPlan: Eino Tool-calling LLM Wrapper (llm package)

## Objective
Provide a small Go package `llm` that:
1) Creates a tool-calling chat model routed by protocol (OPENAI_COMPAT / CLAUDE_COMPAT) with optional BaseURL.
2) Runs a tool-call loop that can:
   - allow tool calls optionally, or require at least one tool, or require an exact tool
   - validate tool arguments before execution (and produce structured validation issues)
   - execute local tools and MCP tools (MCP tools are provided by caller)
   - on successful execution, either:
     - return tool result directly and stop (no further model call), or
     - feed tool result back to the model and return the model’s final answer, or
     - return both

This is a new standalone `llm` project; later it will be moved into a tools repo under an `llm/` directory.

## References
- Eino ChatModel guide: ToolCallingChatModel and WithTools(...) capability.
- Eino tool / ToolsNode guides: tool definitions and schema-oriented tool parameters.
- MCPTool integration: use mcp.GetTools(ctx, &mcp.Config{Cli: cli}) to fetch tools from an already-initialized MCP client.
  IMPORTANT: This wrapper MUST NOT initialize or manage MCP client lifecycle; caller owns that.

## Public API (must match)

### Enums / Types
- type ModelProtocol string
  - const OPENAI_COMPAT ModelProtocol = "OPENAI_COMPAT"
  - const CLAUDE_COMPAT ModelProtocol = "CLAUDE_COMPAT"

- type ToolResultPolicy string
  - const RETURN_FINAL_ANSWER ToolResultPolicy = "RETURN_FINAL_ANSWER"
  - const RETURN_TOOL_RESULT ToolResultPolicy = "RETURN_TOOL_RESULT"
  - const RETURN_BOTH ToolResultPolicy = "RETURN_BOTH"

- type ToolCallMode string
  - const TOOL_OPTIONAL ToolCallMode = "TOOL_OPTIONAL"
  - const TOOL_REQUIRED_ONE ToolCallMode = "TOOL_REQUIRED_ONE"
  - const TOOL_REQUIRED_EXACT ToolCallMode = "TOOL_REQUIRED_EXACT"

- type ToolCallPolicy struct {
    Mode ToolCallMode

    // AllowedTools:
    // - nil/empty: allow all tools provided to WithTools(...)
    // - non-empty: allow only tool names listed here
    AllowedTools []string

    // RequiredToolName is used only when Mode == TOOL_REQUIRED_EXACT
    RequiredToolName string
  }

- type ModelConfig struct {
    // routing
    Protocol ModelProtocol
    BaseURL  string
    APIKey   string
    Model    string
    Timeout  time.Duration

    // sampling (all optional; apply where supported by the chosen client)
    MaxTokens   *int
    Temperature *float32
    TopP        *float32
    Stop        []string

    // tool behavior
    ToolCallPolicy   ToolCallPolicy
    ToolResultPolicy ToolResultPolicy
  }

- type RunOptions struct {
    // default: 3
    MaxRetries int
  }

- type StopReason string
  - const STOP_MODEL_FINAL StopReason = "MODEL_FINAL"
  - const STOP_TOOL_RESULT_RETURNED StopReason = "TOOL_RESULT_RETURNED"
  - const STOP_MAX_RETRIES StopReason = "MAX_RETRIES"
  - const STOP_ERROR StopReason = "ERROR"

- type RunResult struct {
    // FinalText is present when a final answer is generated by the model.
    FinalText string

    ToolName string
    // ToolArgs is the exact args JSON from the tool call.
    ToolArgs json.RawMessage
    // ToolResult is the raw tool output JSON (preferred).
    ToolResult json.RawMessage

    StopReason StopReason
  }

### Functions
- NewToolCallingModel(cfg ModelConfig) (model.ToolCallingChatModel, error)
  - Route by cfg.Protocol:
    - OPENAI_COMPAT -> openai-compatible chat model client (BaseURL optional; APIKey required)
    - CLAUDE_COMPAT -> claude-compatible chat model client (BaseURL optional; APIKey required)
  - Apply cfg.Timeout and sampling parameters where supported.
  - MUST return a ToolCallingChatModel (so it can WithTools).

- RunToolCallLoop(ctx context.Context, m model.ToolCallingChatModel, tools []tool.InvokableTool, opts RunOptions) (RunResult, error)
  - Bind tools via m.WithTools(tools...)
  - Then run the tool-call loop state machine described below.

## Tool-call loop state machine

### Allowed tool set
- If ToolCallPolicy.AllowedTools is empty => allowed = all bound tool names.
- Else allowed = intersection(bound tools, AllowedTools).
- If a tool call references a name not in allowed => invalid tool call.

### Mode behaviors
1) TOOL_OPTIONAL
  - If model returns no tool call => return FinalText immediately (STOP_MODEL_FINAL).
  - If model calls a tool => validate & execute.

2) TOOL_REQUIRED_ONE
  - If model returns no tool call => feedback "must call one tool" and retry.
  - If model calls a tool not allowed => feedback "tool not allowed" and retry.
  - Otherwise validate & execute.

3) TOOL_REQUIRED_EXACT
  - If model returns no tool call => feedback "must call required tool" and retry.
  - If model tool != RequiredToolName => feedback "must call tool X" and retry.
  - Otherwise validate & execute.

### Validation
- Validate tool args before execution.
- On validation failure, feed back a STRUCTURED error object to the model and retry:
  {
    "tool_name": "<name>",
    "error_type": "SCHEMA_VALIDATION_ERROR",
    "message": "arguments are invalid",
    "issues": [
      {"path":"$.field","expected":"string","actual":"number","hint":"field must be a string"}
    ],
    "instruction": "Please call the same tool again with a complete corrected arguments object. Do not output natural language."
  }
- The validation mechanism can be minimal initially:
  - required fields presence
  - basic type checks for string/number/bool/object/array
  - no unknown fields if tool schema specifies strictness (if available)
  - NOTE: design it so it can be swapped to a full JSON Schema validator later.

### Execution
- Execute the tool and obtain a JSON result. (If tool returns non-JSON, wrap it as JSON string.)
- After success:
  - RETURN_TOOL_RESULT => return RunResult with ToolResult and StopReason=STOP_TOOL_RESULT_RETURNED (no further model call).
  - RETURN_FINAL_ANSWER => feed tool result back to model and get FinalText, return StopReason=STOP_MODEL_FINAL.
  - RETURN_BOTH => do RETURN_FINAL_ANSWER but also return ToolResult.

### Feedback templates (short + strict)
- No tool call when TOOL_REQUIRED_ONE:
  "You must call a tool to complete the task. Choose one from: <allowed_tools>. Do not output natural language; output only the tool call."
- Tool not allowed:
  "Tool <name> is not allowed. Choose one from: <allowed_tools> and call it."
- No tool or wrong tool when TOOL_REQUIRED_EXACT:
  "You must call tool <RequiredToolName>. Do not output natural language; output only the tool call."

### Retry limit
- Use opts.MaxRetries (default 3).
- If exceeded, return StopReason=STOP_MAX_RETRIES plus an error describing last failure.

## MCP integration requirement
- The wrapper does NOT create MCP clients.
- Caller may obtain MCP tools like:
  tools, err := mcp.GetTools(ctx, &mcp.Config{Cli: cli})
- Then caller passes tools into RunToolCallLoop (or pre-binds via WithTools).
- The wrapper treats MCP tools the same as local tools.
